一、总体处理顺序（建议固化为标准流水线）
Step 0：统一时基（必须做）
对每个 track，按 frame_index 建立完整的规则时间轴：
从 f_min … f_max 的每一帧都占一个位置（哪怕没有检测，也要有一行，置为 NaN/缺测标记）。
这一点决定了你后面所有“速度/加速度”都能用真实帧间隔计算，而不是被缺帧放大。
Step 1：轨迹级质量门控（决定：删/切/留）
先不插值，先做体检：缺失比例、最大断档、有效点数、速度是否离谱等。
Step 2：缺口级处理（决定：插值/预测/不补）
把每个断档 gap 分级处理：小缺口可以插值，大缺口只能预测且降权，更大缺口直接切段或删。
Step 3：点级去噪（异常点处理）
在“规则时基 + 补真后”的序列上，做鲁棒去噪（中值/MAD/Huber 等）。
Step 4：平滑（RTS/低通/样条）
最后再做 RTS 或其他平滑，让结果稳定且符合你“视频基本匀速”的先验。
你之前感觉“平滑其次、应先插值”，关键原因就是：平滑不能凭空创造中间缺失的运动过程，最多只能“把两端连起来”，而缺帧导致的速度爆点本质是时基不规则 + 差分误用 dt。
二、轨迹级质量门控（删 / 切 / 留）：一个可泛化的“体检表”
对每条轨迹先算这些指标（你已经有不少在 diagnostics 表里了）：
N = frames：有效观测点数
span = f_max - f_min + 1：覆盖跨度
missing_ratio = 1 - N/span：缺失比例
max_gap：最大连续缺失帧数（相邻观测帧差值-1）
gap_count：断档次数
v95 / vmax：速度分位与最大值（建议基于世界坐标）
vmax_naive / vmax：缺帧放大因子（用于判断“爆点主要来自缺帧还是抖动/误检”）
轨迹级决策（推荐阈值模板）
下面阈值是“可普遍使用的默认模板”，之后可以用你全数据集的统计分布再微调（比如用 P90/P95 做自适应）。
A. 直接删除（不可挽回）
满足任意一条就删（或至少不进入数据集）：
N < N_min：有效点太少（推荐 N_min = max(10, 0.5秒×fps)，25fps 时约 12–15）
missing_ratio > R_drop：缺失比例太高（推荐 R_drop = 0.60；做数据集时可更严格到 0.50）
max_gap > G_drop 且 gap_count 不小：最长断档过长，且不是偶发一次（推荐 G_drop = 2秒×fps，25fps 时 50）
物理离谱：v95 或 vmax 超过场景上限太多（比如城市路口车辆你可以设 vmax_limit=40 m/s、行人/电动车/摩托车 vmax_limit=10 m/s，超出就删或标记异常）
B. 切段保留（整体不行，但局部可用）
如果：
missing_ratio 不算极端，但 max_gap 很大（例如 > 1秒×fps），
建议把轨迹按大缺口切成多个 segment：每段单独进入后续补真和平滑；段太短再删。
C. 直接进入补真（可救）
典型条件：
missing_ratio ≤ 0.40 且 max_gap ≤ 1秒×fps，且速度统计大体合理。
你提到“如果缺失比例太大无法挽回就删除”，这里的 R_drop 和 G_drop 就是把“无法挽回”量化成规则。做数据集建议更严一些，因为你追求物理一致和整体平滑。
三、缺口级补真策略（核心）：按 gap 分层处理
设定三到四档 gap（以 fps 归一化，换任何视频都能用）：
小缺口：gap ≤ G1 = 4（约 0.12s@29.97fps）
中缺口：G1 < gap ≤ G2 = 12（约 0.4s）
大缺口：G2 < gap ≤ G3 = 30（约 1.0s）
超大缺口：gap > G3（>1秒）
1) 小缺口（gap ≤ 4）：插值填补，视为“漏检”
适用假设：目标连续运动，检测偶发漏了几帧。
推荐方式（从强到弱）：
位置在世界坐标上做线性插值（足够稳健）
或者用“恒速度插值”（用缺口两端速度估计更平滑）
同时建议：
对插值段打标签 fill_type = linear，后续评估时可以区分真实观测与补点。
2) 中缺口（4 < gap ≤ 12）：插值 + 物理约束校验
适用假设：仍可能是漏检，但已经长到可能发生转向/变速。
策略：
仍可以插值，但必须做约束检查：
插值后每帧速度不能超过 vmax_limit
加速度不能超过 amax_limit（车辆可取 3–5 m/s² 做保守，行人/电动车/摩托车 1–2 m/s²）
约束不通过：不直接删整条轨迹，优先把该缺口升级为“大缺口策略”（下面第 3 类）
3) 大缺口（12< gap ≤ 30）：不建议“硬插值”，改为“预测 + 降权”或“切段”
适用假设：中间发生过你看不见的动作，硬插值会编造运动。
两种选择：
做数据集时偏保守：直接切段（缺口前后当成两段轨迹），避免造假。
若必须连续：使用运动模型预测（比如恒速度/恒加速度的卡尔曼前向预测），但要：
给预测点更低权重（后续 RTS 时 measurement noise 更大）
给该段打 fill_type = predict_low_conf
不输出该段的高阶物理量（例如加速度/航向角）或标为低可信------------------我选择必须连续的方案
4) 超大缺口（gap > 30）：原则上不补
对你“视频基本正常、目标不会极端运动”的数据集目标来说，>1 秒没观测，补出来的连续轨迹几乎必然失真。
推荐：
直接切段；段太短则删
或者整条轨迹判为低质量直接剔除（视你对召回率/精度的要求）
四、速度/静止问题的专门处理（让“静止车速度不为 0”消失）
你说的静止车辆仍有速度，本质是检测抖动 + 映射放大。补真之后再做下面这个“静止门控”，会非常有效，而且不依赖场景：
静止门控（带滞回，避免抖动）
设定：
速度阈值 v_stop（例如 0.2–0.3 m/s，取决于你的世界坐标标定噪声）
连续帧数 K_stop（例如 0.5秒×fps，25fps 取 12–15）
规则：
如果连续 K_stop 帧满足 |v| < v_stop，则将该段标记为 stationary，并把速度钳制到 0（或非常接近 0）。
恢复运动也要连续超过阈值一段时间（滞回），避免“停—动—停”快速翻转。
这条规则对任何检测器都通用，因为它只用速度序列本身，并且你的场景先验（车辆不会无缘无故微动）非常吻合。
