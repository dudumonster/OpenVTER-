traj_info结构：
Entry type: <class 'tuple'>, length: 3
  element[0] type: <class 'int'>, value shape/len: 0
  element[1] type: <class 'int'>, value shape/len: 0
  element[2] type: <class 'numpy.ndarray'>, value shape/len: (95, 20)

这 20 列对应的字段顺序为：
1-8. 像素四点坐标 x1_px, y1_px, …, x4_px, y4_px
9. score（检测置信度）
10. category（检测类别）
11. track_id（跟踪 ID）
12-19. 世界坐标四点 x1_world … y4_world（说明 road_config 提供了像素→世界坐标矩阵）
20. lane_id（车道编号，因为 road_config 里定义了 lane_* 多边形）

因此 traj_info 实际存的是“每帧的所有轨迹数组”。如果你遍历 traj_info，对 element[2] 的每一行按上述列名解读，就能得到每辆车在该帧的全部信息，然后再按 track_id 拼起来，就可以导出高D式的轨迹表了。

🎞 基础信息	recording_id	文件名/视频名（此处为 det_bbox_result_cropped_1min）
	frame_index	当前帧编号（从 0 开始）
	output_frame	输出帧编号（与 frame_index 一致）
	frame_time	帧时间（此处为空 NaN，说明视频中未记录时间戳）
⚙ 检测框坐标（像素系）	x1_px ~ y4_px	检测框的 4 个顶点像素坐标（单位：px）
📈 检测置信度与类别	score	模型检测置信度（0~1）
	category	目标类别（此处全为 0，说明只检测了一类目标，如“车辆”）
🚗 跟踪信息	track_id	跟踪目标编号（同一目标跨帧保持一致）
	track_lifetime	目标已出现的帧数（生命周期计数）
🌍 世界坐标系（投影坐标）	x1_world ~ y4_world	检测框四个角在世界坐标中的位置（经过透视转换）
	xCenter_world, yCenter_world	目标中心点的世界坐标位置
🛣 车道信息	lane_id	车辆所在车道编号（1~8）
📍 中心点坐标（像素系）	xCenter_px, yCenter_px	检测框中心像素坐标（由四点均值计算）
