# 基于现有论文与 OpenVTER 项目的识别模型训练思路

## 1. 你的研究主线应该怎么讲

你的方向不是单纯“换一个检测模型提高精度”，而是：

> 面向中国复杂道路、环岛与人车混行场景，构建多类别交通参与者的航拍轨迹提取框架；在 OpenVTER 的旋转框轨迹提取基础上，将识别对象从机动车扩展到机动车、非机动车和弱势交通参与者，并通过更适合小目标和多姿态目标的 OBB 检测训练策略提升轨迹与交互行为提取质量。

这里的关键是把“感知模型精度”放回“轨迹数据集构建和交互分析”的大目标里。否则只做检测器替换，创新性会显得薄。

## 2. 这些论文分别在讲什么

### OpenVTER

OpenVTER 的故事是：航拍视频可以提供完整交通视野，但会遇到视频抖动、小目标、车辆旋转姿态、多道路类型泛化和轨迹后处理问题。因此它提出完整框架：视频稳定、图像分块、YOLOX-R 旋转框检测、SORT-R 旋转框跟踪和后处理。

它的核心方法是 YOLOX-R：基于 YOLOX，输出旋转边界框。论文强调 RBB/OBB 比水平框更贴合车辆外形，也能提供朝向信息。YOLOX-R 用 BBA Vectors 避免直接角度回归在 0/360 度附近不稳定的问题，并用两阶段训练：第一阶段先训练 HBB 检测能力，第二阶段冻结主干和检测分支，训练旋转框方向能力。

它的训练数据不是普通 COCO/VisDrone 水平框，而是 DroneVehicle 和 UAV-ROD 这种带旋转框标注的数据集。这正是你现在卡住的点：OBB 检测不能只拿普通水平框数据直接训练，需要角点或旋转框标注。

### openDD

openDD 的故事是：自动驾驶行为预测需要完整轨迹和地图，环岛交互强、无信号控制、车辆互相影响明显，因此构建了大规模无人机环岛轨迹数据集。它覆盖 7 个环岛、501 次无人机飞行、超过 62 小时轨迹、84,774 条轨迹，并提供 HD map。

对你有用的点不是模型，而是论文叙事方式：它把“场景类型稀缺”作为创新点。你的数据如果覆盖中国多城市复杂环岛、人车混行、多类别参与者，也可以用类似逻辑讲“现有数据集多集中在结构化道路或国外场景，复杂中国环岛/混行场景不足”。

### SAHI

SAHI 的故事是：航拍和监控中的小目标像素少，直接把大图 resize 到模型输入会损失细节。因此它提出 sliced fine-tuning 和 sliced inference：训练时把大图切成重叠 patch，推理时也切片检测，再合并重复框。它能在 VisDrone/xView 上明显提升小目标 AP。

对你的项目非常关键：OpenVTER 其实已经有类似思想，视频配置里有 `split_gap`、`subsize_height`、`subsize_width`，相当于分块检测。你可以把 SAHI 作为理论支撑，把“切片训练 + 切片推理 + 全局旋转 NMS”作为提升小目标识别的实验变量。

### UAVDT

UAVDT 的故事是：无人机检测/跟踪数据有高密度、小目标、相机运动、遮挡、视角变化等挑战，普通检测和跟踪方法在这种场景上性能下降明显。它的价值是给你提供问题定义语言：复杂航拍识别难点不是单个模型不够强，而是小目标、密集遮挡、视角变化和多类别相似外观共同造成的。

你的论文可以把这些作为检测任务难点：小目标 VRU、三轮车/摩托车/自行车类间相似、行人和骑行者尺度差异大、环岛内方向变化大、遮挡频繁。

### AD4CHE

AD4CHE 的故事是：中国拥堵高速/快速路缺少公开自然驾驶数据集，因此用无人机采集 4 个中国城市、5.12 小时拥堵交通数据，提取车辆轨迹、类别、车道信息、TTC/THW、车辆朝向、横摆角速度等，并进一步分析中国特色拥堵切入场景。

对你有用的是两点。第一，它明确把“中国交通场景”作为创新背景。第二，它不是停留在检测，而是从检测跟踪结果继续生成行为参数和典型场景。这提示你：检测模型训练应该服务于后续“交互行为提取”。

### VRUD 与王子煜硕士论文

VRUD/硕士论文的故事和你的方向最接近：现有数据集偏结构化道路，缺少高密度 VRU、无序混行、遮挡严重的城市村庄/复杂混行场景。因此它用 4K/30Hz、80m 高度无人机数据构建 VRU 交互数据，包含 4 小时视频、11,479 条 VRU 轨迹和 1,939 条车辆轨迹，并提取 4,002 个交互事件。

硕士论文里更具体：它用 YOLO11-obb + ByteTrack 获取 7 类交通参与者轨迹，7 类为行人、自行车、电动摩托车、电动三轮车、轿车、货车、客车。标注方式是八参数法，即 4 个角点坐标；每 2 秒抽 1 帧，总计 2,252 张图、198,978 个目标，训练/验证/测试为 1125/375/752，输入分辨率 1440 x 1440，AdamW，batch 16，200 epochs，最终 Precision 0.939、Recall 0.965、mAP@0.5 0.974、mAP@0.5:0.95 0.805。

这篇给了你最直接的可复现路线：复杂混行场景下可以不沿用 YOLOX-R，而改用现代 OBB 检测器，并以 OBB 标注作为训练核心。

## 3. 结合当前仓库，模型路线怎么选

当前 OpenVTER 仓库里检测入口在 `VehicleDetModule`，已经支持 `yolox_r`、`centernet_bbavectors`、`mmrotate`、`yolov5` 四类模型。其中 `mmrotate` wrapper 会把模型输出的 rbox 转成四点 qbox，正好符合 OpenVTER 后续统一格式。仓库里也有多检测器融合配置：机动车走旋转检测，VRU 可以另走 YOLOv5/TPH-YOLOv5 水平框，再映射到全局类别。

因此你的路线有三种：

1. **最推荐：MMRotate/RTMDet-R 或 Rotated RetinaNet/Oriented R-CNN 路线。**
   你把自己的标注转成 DOTA/COCO-OBB 格式，训练一个多类别 OBB 检测模型，然后直接接入仓库已有 `mmrotate` 推理接口。这条路线与 OpenVTER 兼容最好，也更适合作为论文实验，因为可以和 YOLOX-R、CenterNet-BBAVectors、YOLO11-obb 做对比。

2. **最快出结果：Ultralytics YOLO11-OBB 路线。**
   按硕士论文路线训练 YOLO11x-obb 或 YOLO11m-obb，然后在 OpenVTER 里新增一个 wrapper，把 YOLO11-OBB 输出的四角点转成 OpenVTER 的 10 列格式 `[x1,y1,x2,y2,x3,y3,x4,y4,score,cls]`。这条路线训练方便，效果可能也好，但需要你补一个集成接口。

3. **不建议作为主线：继续训练 YOLOX-R。**
   OpenVTER 当前仓库主要保留了 YOLOX-R 的 JIT 推理，不完整包含训练工程。除非你拿到原作者完整训练代码，否则继续复刻 YOLOX-R 的成本高于收益。

TPH-YOLOv5 可以作为补充基线或 VRU 水平框检测器，但不应该作为主创新模型，因为它输出 HBB，不能稳定提供自行车、摩托车、三轮车等参与者的朝向。

## 4. OBB 训练卡点怎么解决

你说的 OVB 应该是 OBB/RBB，即 oriented/rotated bounding box。训练 OBB 模型必须解决 4 件事：

1. **标注格式。**
   推荐保留八参数角点标注：`class x1 y1 x2 y2 x3 y3 x4 y4`。这是 DOTA/YOLO-OBB/MMRotate 都能转换的核心格式。不要先退化成水平框，否则朝向信息丢了。

2. **类别体系。**
   建议先收敛到 7 类：`car, truck, bus, pedestrian, bicycle, motorcycle/e-bike, tricycle`。如果数据量足够，再拆 `van, freight_car, awning-tricycle, people/rider`。类别太细会导致长尾类别 AP 不稳定。

3. **小目标策略。**
   训练和推理都采用切片。训练集从原始 4K/5.4K 图中切 1024 或 1440 patch，overlap 20%-30%；推理时沿用 OpenVTER 的分块检测，并保证 overlap 大于最大目标长度。最后用全局 rotated NMS 合并重复框。

4. **行人角度问题。**
   行人的 OBB 朝向语义弱，行人框更像检测位置而非真实朝向。论文里要说明：车辆、骑行者、三轮车的角度用于朝向/轨迹分析；行人类别主要使用中心点和尺寸，角度只作为检测框几何输出，不作为行为朝向指标。

## 5. 推荐实验矩阵

第一组是检测模型对比：

| 模型 | 框类型 | 作用 |
|---|---|---|
| CenterNet-BBAVectors / YOLOX-R | OBB | OpenVTER 原始强基线 |
| TPH-YOLOv5 | HBB | 小目标水平框基线 |
| YOLO11-OBB 或 RTMDet-R | OBB | 你的主模型 |
| 主模型 + sliced fine-tuning | OBB | 验证切片训练收益 |
| 主模型 + sliced inference | OBB | 验证切片推理收益 |

第二组是类别与场景泛化：

| 实验 | 目的 |
|---|---|
| 机动车 3/5 类训练 | 对齐 OpenVTER 原始任务 |
| 7 类交通参与者训练 | 证明扩展到混合交通 |
| 按城市/环岛留一测试 | 证明跨城市、跨道路结构泛化 |
| 白天/夜间/高密度/遮挡分组测试 | 证明复杂条件鲁棒性 |

第三组是轨迹层指标：

| 指标 | 为什么重要 |
|---|---|
| mAP@0.5, mAP@0.75, mAP@0.5:0.95 | 检测精度，尤其 mAP@0.75 更能反映旋转框贴合度 |
| Precision/Recall by class | 检查行人、摩托、三轮车等长尾类别 |
| IDF1 / MOTA / ID switch | 检测提升是否真的改善跟踪 |
| 轨迹完整率 CR | 对齐 OpenVTER 原论文 |
| 速度/相对距离 MAE 或 MAPE | 证明轨迹能用于交互分析 |

## 6. 可以写成论文创新点的版本

建议把创新点组织成 3 条：

1. **复杂中国道路多类别航拍轨迹数据集。**
   相比 openDD、AD4CHE、VRUD，你的数据面向中国多城市复杂环岛/混行道路，覆盖机动车、非机动车和 VRU，强调道路结构、交通参与者类型和交互行为的复杂性。

2. **面向多类别混合交通参与者的 OBB 感知训练策略。**
   在 OpenVTER 车辆 RBB 检测基础上，扩展为 7 类或更多交通参与者 OBB 检测；通过八参数 OBB 标注、切片微调、切片推理和全局 rotated NMS，提高小目标、密集目标和不同朝向目标的识别精度。

3. **从检测精度到轨迹/交互质量的闭环评价。**
   不只报告 mAP，还报告跟踪 ID 稳定性、轨迹完整率、速度/距离误差、交互事件提取数量和质量，证明识别模型提升会传导到轨迹数据集和交互行为分析。

## 7. 我建议你下一步直接做什么

第一步，先不要急着全量训练。先从你们数据里抽一个小闭环数据集：

- 3 个城市或 3 个典型环岛/路口；
- 每个场景抽 5-10 分钟视频；
- 每 1-2 秒抽 1 帧；
- 标 7 类 OBB；
- 保证每类至少几千个实例，长尾类别如 bus/truck/tricycle 可以有意识补采样。

第二步，做两个 baseline：

- OpenVTER 原始 `YOLOX-R/CenterNet-BBAVectors` 在机动车上的效果；
- YOLO11-OBB 或 MMRotate 主模型在 7 类上的效果。

第三步，再加切片实验：

- 原图训练 vs 切片训练；
- 整图推理 vs 切片推理；
- 不同 patch size 和 overlap。

第四步，把最优模型接回 OpenVTER，跑完整视频，比较轨迹完整率、ID switch、速度和相对距离误差。只有跑到轨迹层，论文才不是普通检测论文，而是 OpenVTER 基础上的交通轨迹数据集构建方法论文。
